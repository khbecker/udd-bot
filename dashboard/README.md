# Kernel team package dashboard

A local web dashboard over the [UDD](https://udd.debian.org/) public mirror
that answers the question an Ubuntu developer actually has about each tracked
package: *does this need a merge, a sync, or nothing at all?*

The package list is read from `../package-list.txt`, which stays the single
source of truth shared with the UDD link generated by `build.py`.

## Setup

```bash
make venv
```

or manually:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

## Running

```bash
make run
# or
python3 app.py
```

Then open http://127.0.0.1:5000.

Options:

| Option | Description |
| --- | --- |
| `--host HOST` | Address to bind to (default `127.0.0.1`) |
| `--port PORT` | Port to bind to (default `5000`) |
| `--debug` | Flask debug/reload mode |
| `--package-list PATH` | Package list to read (default `../package-list.txt`) |
| `--series NAME` | Override the devel series |
| `--lts NAME` | Override the LTS series |

Environment variables:

| Variable | Description |
| --- | --- |
| `UDD_DEVEL_SERIES` | Override the devel series |
| `UDD_LTS_SERIES` | Override the LTS series |
| `UDD_DIF_DATE` | Debian Import Freeze date, `YYYY-MM-DD` |

The devel and LTS series are resolved with `ubuntu-distro-info`. If that is
not installed the dashboard falls back to a hardcoded guess and says so in the
header rather than pretending to know.

## Package states

The dashboard reports one state per package, derived from the devel release
pocket, the devel `-proposed` pocket and Debian sid. The key distinction is
whether Ubuntu carries a delta, because that determines whether the package
syncs by itself or needs a human.

| State | Meaning | Action |
| --- | --- | --- |
| `synced` | No Ubuntu delta, identical to Debian | None |
| `autosync-pending` | No delta, Debian is newer | None before DIF; manual sync after |
| `delta-current` | Ubuntu carries a delta, Debian is not ahead | None |
| `merge-needed` | Ubuntu carries a delta and Debian is newer | Merge |
| `sync-available` | Ubuntu packaged this upstream release first (`-0ubuntuN`) and Debian has caught up | Probably sync, after checking the delta |
| `in-proposed` | The release pocket is behind, but the upload is already in `-proposed` | Chase proposed-migration |
| `not-in-devel` | Absent from the devel series | Investigate removal |
| `ubuntu-only` | No Debian counterpart | Maintained in Ubuntu |
| `ubuntu-ahead` | Ahead of Debian with no Ubuntu revision marker | None |

### Debian Import Freeze

Before DIF, packages with no Ubuntu delta sync from Debian automatically and
need no human action. After DIF autosync stops and every one of them needs a
manual sync. The banner counts down to the freeze and highlights how many
merges are still outstanding, since those need to land before autosync stops.

Known DIF dates are held in `KNOWN_DIF_DATES` in `series.py`, taken from the
published release schedules:

| Series | DIF | Source |
| --- | --- | --- |
| `stonking` (26.10) | 2026-08-20 | [26.10 release schedule](https://documentation.ubuntu.com/release-notes/26.10/schedule/) |

Set `UDD_DIF_DATE=YYYY-MM-DD` to override, or to configure a cycle that is not
in the table yet. A series with no known date shows "unknown" rather than a
guess, because guessing wrong inverts the advice for every package with no
delta.

### Upstream status

The upstream column comes from Debian's watch files and is a **separate axis**
from the Ubuntu/Debian comparison. It is shown in three states: up to date,
newer available, and unknown. Unknown covers missing watch data and unreliable
results such as `only older package available`, and is rendered grey — it does
not mean the package is fine.

## Prompts

Each row offers only the prompts valid for its state, so the dashboard never
suggests preparing an upload for something already sitting in `-proposed`.
Prompts are plain Markdown templates in `prompts/`, rendered server-side with
the package's real versions, component, delta and last uploader, then copied
to the clipboard for use with an AI assistant.

- `merge.md` — rebase the Ubuntu delta onto a newer Debian version, and draft
  the "Remaining changes" / "Dropped changes" changelog blocks.
- `sync.md` — decide whether the Ubuntu delta can be dropped in favour of a
  plain `syncpackage`, with the evidence needed to justify it.
- `new-upstream-debian.md` — package a new upstream release **in Debian**, so
  Ubuntu picks it up by sync or merge.
- `investigate-proposed.md` — find the proposed-migration blocker.

New upstream versions deliberately target Debian rather than Ubuntu. Importing
upstream releases straight into Ubuntu creates a permanent delta that has to be
carried at every future merge.

Edit the Markdown files to change the prompts; no Python changes are needed.

## API

| Endpoint | Description |
| --- | --- |
| `GET /` | The dashboard. `?refresh=1` forces a refetch. |
| `GET /api/packages` | All package data as JSON |
| `GET /api/prompt/<pkg>?kind=<kind>` | A rendered prompt |

Data is cached for five minutes. If UDD becomes unreachable the dashboard keeps
serving the last good data with a visible warning rather than failing outright.

## Styling

The UI uses [Vanilla Framework](https://vanillaframework.io/), loaded from
`ubuntu.com` with the same stylesheet URL that
[kernel.ubuntu.com](https://kernel.ubuntu.com/) uses, so the dashboard matches
current Ubuntu styling and picks up changes to it. Package states map onto
Vanilla status labels: positive for no action, information for informational,
caution for "look at this", negative for "a human must act".

`static/dashboard.css` holds only the rules Vanilla has no component for —
the filter bar layout, monospace version cells and the prompt block. Keep it
small: if Vanilla has a class for it, use the class.

One deliberate exception: the row action buttons are restyled smaller and
outlined. Vanilla's filled buttons look almost identical to the filled status
labels in the State column, so at a glance it was not obvious which cells were
clickable. Actions are now outlined, rounded, raised and respond to hover,
focus and press, while status labels are square, flat and have no pointer
cursor. The trailing ellipsis on an action label is the usual convention for
"opens a dialog".

Because the stylesheet is remote, the page is unstyled when offline. That is
an accepted trade-off: the dashboard queries UDD over the network, so it
cannot do anything useful offline anyway. Vendor
`static/vanilla.css` and change the `<link>` in `templates/index.html` if you
need it to work without network access.

## Tests

```bash
make test
```

This is an experimental tool, so the suite is deliberately small: it covers
the cases that were previously wrong rather than every possible input. Version
comparison is checked against `dpkg --compare-versions` itself, and the
classifier is pinned to real archive data for the tracked packages.

## Known limitations

- Bug counts are not shown. They made the table harder to scan without
  changing any merge or sync decision, and the `ubuntu_bugs` tables on the
  public UDD mirror are empty anyway. Each row links to the Debian tracker.
- Autopkgtest and proposed-migration results are not in UDD, so the dashboard
  links out to the update-excuses page rather than showing status inline.
